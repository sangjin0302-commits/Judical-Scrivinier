# 개념과 공식 문제의 연결

기준일: 2026-10-27. 연결정보의 원본은 개념 관리표 `개념_문제연계`다. 문제 관리표에 중복 연결표를 만들지 않는다.

## 확인 결과

`개념_문제연계!A5:L25`의 기존 21건을 읽어 `mapping/concept-problem-proposals.csv`에 정리했다. 20건이 15개 단원에 연결되어 있고 기재된 단원ID는 모두 `개념_단원마스터`에 존재한다. 19행은 단원ID가 공란인 미매칭 1건이다. 안정키 `SRC-CIV-005|2025-제31회-문1-소문항2`와 원본의 `검토 필요` 상태를 보존했다. 새 연결을 추측해 만들거나 원본에 기록하지 않았다.

기존 검증 상태에 PDF 대조 대기·검토 필요가 남아 있다. 공식 문제원장의 안정키·사용상태를 이번에 재확인하지 않았으므로 `official_key_rechecked`를 부정값으로 기록했다. 단원과 안정키가 기존 연결표에 함께 있다는 사실만으로 법리상 대응이 검증되었다고 판단하지 않는다.

## 실제 학습 순서

1. 원본의 오늘 학습에서 단원ID를 확인한다.
2. 해당 단원의 강의만 읽는다.
3. 별도 회상 질문을 제시하고 실제 답변을 받은 뒤 평가한다.
4. 관련 공식 문제 학습을 요청받으면 연결표의 검증 상태를 확인한다.
5. 공식 출제는 해당 브리지의 상태·범위·후보 순서 규칙을 따른다. 후보 상위 N개를 임의로 바꾸지 않는다.
6. 개념 회상과 공식 점수를 각각 원본에 기록한다. 연결표는 점수를 합치는 수단이 아니다.

현재 범위에 관련 문제가 없으면 그 사실을 알린다. 연결 목록에서 임의로 문제를 가져와 정식 세트로 만들지 않는다.

## 연결 보강 절차

보강할 때는 단원ID와 PDF 범위를 먼저 확인하고, 공식 원장에서 필요한 안정키·분류·사용상태만 좁게 확인한다. 문제 지문·채점키의 전체 복제나 모든 법리 재검증은 하지 않는다. 실제 쟁점의 대응 근거를 확보한 후보만 검토 목록에 추가한다. 사용자 승인 전 원본 연결표에는 쓰지 않는다.

상태는 `기존 등록`, `원장 안정키 확인`, `원문 대응 확인`, `검토 필요`를 구분한다. 확인 날짜와 근거 위치를 함께 남기며, 검증 상태를 한 단계에서 자동으로 건너뛰지 않는다.

기존 연결 21건은 전체 240단원이나 공식 문제은행의 전수 연결을 뜻하지 않는다. 다음 보강 대상은 실제 학습 중 연결이 필요한 단원부터 고른다. 개인 오답 원문은 GitHub에 옮기지 않는다.
