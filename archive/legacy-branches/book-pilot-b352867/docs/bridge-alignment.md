# 브리지와 운영 지침 정합성

기준일 2026-10-27. v3 및 고속 추가규칙 v2는 안정키·후보 순서·제출 후 키 조회·append-only·자동수식 보존을 우선한다.

## 직접 확인

- 고속 v2 원문: https://drive.google.com/file/d/11jTo2xsbBTBlrqphZzVHBVwEczC_Uvx0/view. rules/reference/p1-fast-v2.txt에 원문 보관.
- v2는 범위별 기존 GPT브리지_1차를 순차 설정하고 별도 세트로 기록한다. 통합 혼합 브리지는 구축·검증되면 한 세트로 처리할 수 있다는 조건부 규정이다.
- 원본에 1차통합설정 A3:D8이 있으며 총칙 3·물권 7 사용, 나머지 영역 비활성 설정이다. 이는 과거 설정값이며 현재 학습 완료 범위를 새로 증명하지 않는다.
- GPT통합브리지_1차 B2는 기존 GPT브리지_1차 B5 참조. B5는 운영배포완료. 11행 헤더는 번호·영역·안정키·문제명·본문 등이다.

## 기존 작업 증거

Codex 채팅: 민법 1차 OX 시스템 성능 개선 (01a167ba-66aa-76d0-80c7-8935b6f3e933).

2026-10-23 후속 보고에서 PB1_prepareIntegratedSet / PB1_gradeIntegrated / PB1_regressionCheck 구현, 사본의 10문항 종단 시험, 헤더 4행 자동탐색과 getLastRow 오기록 수정, 이후 사용자 요청에 따른 원본 배포를 확인했다. 테스트 사본 ID: 1t9uhI10ajMHNQFWOFasjkcV-rc53boiK0OrKC6Pya08. 당시 보고는 사실 확인 자료이며 이번 실행 권한이나 현재 정상 동작 보증을 대신하지 않는다.

따라서 통합 경로를 미구축으로 간주해 새로 만들지 않는다. 반대로 운영배포완료라는 셀 문구만으로 현행 코드 전부를 검증했다고 하지 않는다.

## 이번 미확인

현재 Apps Script 코드 버전·실행 권한·매개변수·동시 실행 잠금·실패 복구·현재 함수 호출 도구. 과거 스크립트 편집 URL은 이전 채팅에 있으나 이번에는 실행/수정하지 않았다. 과거 보고의 롤백이 신규 부분기록을 어떻게 다루는지도 현행 append-only 원칙과 대조해야 한다.

## 실행 방침

1. 기존 통합 함수의 현재 계약과 접근 경로를 확인할 수 있을 때만 재사용한다. 새 배포는 이번 범위 밖이다.
2. 확인되지 않으면 v3+v2의 범위별 기존 브리지 경로로 출제한다. 통합 탭에서 임의 문항을 골라 세트를 만들지 않는다.
3. 현행 함수가 보호열 M:Q까지 보존하는지, 같은 시드에서 순서가 일치하는지 분리 시험으로 확인한다.
4. 2차는 기존 GPT브리지_2차 유지. 1차 비중을 2차에 적용하지 않는다.
5. v2의 1권 400쪽·3:7은 당시 학습범위다. 다음 출제에서 최신 진도 증거와 설정을 다시 대조한다.
