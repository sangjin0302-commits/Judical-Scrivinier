# PB1 v2 안정화 상태

기준일: 2026-10-28 KST. 운영 원본·Google Sheets·Docs·Apps Script에는 접근하거나 실행하지 않았다. 이 문서는 저장소 코드와 로컬 합성검사 결과만 기록한다.

## 이번 코드 수정

| 결함 | 수정 |
|---|---|
| 공개 완료 전에 `requestId→setId` 완료 매핑 저장 | 보류 상태와 완료 상태를 분리했다. 세트 행·공개 상태 재검증 뒤에만 완료 매핑을 저장한다. |
| 실패 재시도 때 불완전·비공개 세트 복원 또는 새 세트 중복 | 같은 요청의 보류 세트를 잠금 안에서 복구한다. 행이 일부만 존재하거나 내용이 다르면 새 세트를 만들지 않고 중단한다. |
| 화면 오류 뒤 새 `requestId` 생성 | `sessionStorage`에 보류 ID를 유지하고 출제 성공 뒤에만 지운다. |
| 다른 사용자·비공개 세트 채점 | Apps Script 임시 활성 사용자 키에 요청·세트·답안 예약을 연결하고, 세트 공개 상태와 소유권을 채점 전에 검사한다. |
| OX 기록 뒤 실패 시 다른 답안으로 재시도 가능 | 첫 채점 시 답안 다이제스트를 예약한다. 이후 같은 답안만 복구하고 다른 답안은 기록 전에 거부한다. |
| 출제 부분 실패 뒤 고아 상태 | 보류 상태에 세트ID·시드·안정키·영역을 저장해 0행이면 같은 세트ID로 다시 쓰고, 완전한 비공개 행이면 공개 단계를 재개한다. 부분·불일치는 수동 점검 대상으로 중단한다. |

원본 시트의 수식·드롭다운·보호범위는 수정하지 않는다. 쓰기 열은 기존 계약과 동일하며 OX H, 풀이 M:Q를 덮어쓰지 않는다. 답안 제출 전 채점키 접근도 추가하지 않았다.

## 로컬 검사

- 기존 Python `unittest`: 40개 통과.
- `node --test tests/pb1_fast_safe_node.test.js`: 4개 통과.
- `node --check`로 Apps Script 소스의 JavaScript 문법 통과.
- `git diff --check`: 통과.
- `tools/validate_package.py`: PASS 4,470 / FAIL 0 / 기존 WARN 45.

로컬 검사는 Google 서비스, 실제 계산 수식, 동시 실행, 브라우저 권한을 검증하지 않는다.

## 독립 프로젝트와 실측 상태

독립 Spreadsheet ID와 독립 Apps Script project ID가 제공·검증되지 않았다. 따라서 실제 출제·채점, 8회 동시 호출, 단계별 강제 오류, 수식 보존, PC·모바일, 각 5회 지연시간 측정은 모두 **미실행**이다. 운영 원본과 분리됐다는 증거 없이 `clasp push`, 함수 실행, 배포를 해서는 안 된다.

다음 인수시험을 시작하려면 사용자가 운영 원본이 아닌 Google Sheets 사본 하나와 새 standalone Apps Script 프로젝트 하나를 만들고, 두 ID가 운영 ID와 다름을 확인한 뒤 테스트 계정에만 접근 권한을 주어야 한다. 그 다음 `PB1F_TEST_SPREADSHEET_ID`를 사본 ID로 설정하고 [고정 시험 절차](pb1-benchmark-protocol.md)를 수행한다.

## 남은 위험과 병목

- 임시 활성 사용자 키가 실제 웹앱 배포 방식에서 사용자별로 구분되는지 실측해야 한다. 구분되지 않으면 OAuth 주체를 사용하는 별도 인증 경계가 필요하다.
- 새 세트의 정상 경로도 세트ID 중복 확인과 일부 복구에서 기존 열을 넓게 읽는다. 실제 행 수와 지연시간을 측정한 뒤 검증된 행 인덱스를 추가하되, 속성을 진실의 원천으로 단독 사용하지 않는다.
- OX·풀이 기존 행 탐색과 최종 검증은 아직 전체 유효영역을 읽는다. 행 포인터·연속 구간 인덱스는 실제 시트에서 append-only 성질과 수식 채움 방식을 확인한 뒤 도입한다.
- `SpreadsheetApp.flush()`는 후보 계산, 선택 계산, 기록 수식 확인에 각각 필요할 수 있다. 어느 호출도 측정 없이 제거하지 않는다.
