# 민법 1차 고속 운영 추가규칙 v2 — 전범위 동적 확장형

적용: 기존 「민법 1차 고속 운영 추가규칙 v1」을 이 문서로 대체한다. 다만 「민법 상세 운영 지침 v3」와 프로젝트의 안정키·출제순서·정답키 보호·기록 보존·자동수식 안전 원칙은 그대로 우선한다. 이 규칙은 민법총칙·물권법·채권법·친족법·상속법을 모두 포괄하며, 향후 과목 또는 장이 늘어날 때 새 운영 지침을 작성하지 않는다.

## 1. 출제 범위는 고정값이 아니라 학습 진도 데이터다
1. 1차 OX 출제 가능 범위는 사용자가 실제로 학습했다고 확인한 누적 진도만 반영한다. 기본서 「단기 민법 1·2권」의 기본서_색인.csv와 개념중심 DB의 개념_단원마스터에서 해당 권·편·장·절·PDF 페이지를 대조한다.
2. 현재 확인된 시작 범위는 「단기 민법 1권」 PDF 400쪽까지다. 현재 기본 혼합 비중은 민법총칙 3문제·물권법 7문제(10문제)이며, 이 비중은 영구 규칙이 아닌 현 단계의 설정이다.
3. 채권법 진입, 채권총칙·채권각칙의 진도 확대, 친족법 진입, 상속법 진입, 민법 전범위 완료 시에는 범위 및 비중 설정값만 갱신한다. 기존 출제 지침을 새로 추가하지 않는다. 가족법은 친족법과 상속법을 포함한다.
4. 출제 범위를 뜻하는 “현재 학습범위 전체”와 실제 민법의 “법전 전범위”를 구별한다. 별도 지정 없는 “민법 1차 문제”는 현재 학습 완료 범위 안에서 출제한다. 채권법·가족법 미학습 시에는 법전 전범위를 임의로 열지 않는다. 사용자가 명시적으로 범위를 지정하면 해당 요청과 출제 안전 원칙을 우선한다.
5. 진도 갱신 명령 예: “1권 500쪽까지 읽었어”, “2권 250쪽까지 읽었어”, “채권총칙 ○절까지 완료”, “친족법 끝냈어”, “민법 전범위 완료”. 이는 운영 지침 수정 요청이 아니라 최신 학습범위 알림이다.
6. 진도 증거가 없거나 기본서 페이지와 문제은행 분류의 연결이 불명확하면 새 범위를 임의로 열지 않는다. 진도 정보가 다른 대화에서 확인되지 않으면 연결된 개념 DB의 검증 가능한 독서기록을 우선 살피고, 그래도 판단할 수 없는 부분만 묻는다. 읽지 않은 단원을 완료한 것으로 간주하지 않는다.
7. 브리지가 장(章) 단위까지만 필터링하면 부분 학습 장의 PDF 쪽수 단위까지 출제 제한을 정확히 보장할 수 없음을 인식한다. 후보를 임의 건너뛰지 말고, 검증된 세부 범위 필터가 없으면 실제 지원 범위와 한계를 알린다.

## 2. 출제 비중은 학습 단계별 자동 조정
1. 기본 세트는 1차 OX 10문제다. 사용자 지정 문항수·대상범위·출제모드가 있으면 그 요청을 우선한다.
2. 현재 물권법 학습 단계: 민법총칙 3 + 현재 학습한 물권법 7.
3. 새로운 영역(채권법, 친족법, 상속법 등)을 공부하기 시작한 뒤: 해당 영역의 실제 학습 완료분을 우선하여, 기본 목표로 10문제 중 6~7문제는 최신 학습 영역, 3~4문제는 종전에 학습한 영역에서 출제한다. 아주 좁은 새 진도에는 후보 수에 맞춰 비중을 완화하고, 이후 진도 확대에 따라 점진적으로 높인다. 후보가 부족하거나 사용자가 비중을 지정하면 검증된 후보 수에 맞게 조정한다.
4. 여러 영역이 동시에 새로 학습되거나 10문항으로 모든 영역을 커버하기 어려우면 최근 학습 진도, 확인된 오답·취약 기록, 마지막 출제 구성을 기준으로 범위별 묶음을 순환한다. 분배를 이유로 브리지의 상위 N개 안정키를 임의 재선정하지 않는다.
5. 사용자가 “민법 전범위 완료”라고 알리고 그 범위가 확인된 뒤에만 법전 전범위로 확대한다. 그때는 민법총칙·물권법·채권법·친족법·상속법을 모두 출제 가능 범위로 두고, 확인된 오답·취약도·복습주기·미풀이 후보를 반영해 배분한다. 확인할 취약 데이터가 없다면 영역 균형 및 세트 간 순환을 기본으로 한다. 전범위 = 항상 특정 파트 비율 고정이라는 뜻이 아니다.
6. 출제 범위에 편입되지 않은 미학습 부분은 계속 제외한다. 장기 미복습 단원의 비중을 조절할 수 있으나, 실제 풀지 않은 문제를 오답으로 취급하지 않는다.

## 3. 문제은행의 실제 분류에 맞추어 범위 설정
1. 1차 문제 DB는 민법_문제판례중심_회독관리표의 GPT브리지_1차를 사용한다. B7=출제모드, B8=범위, B9=문항수, B10=새 셔플시드다.
2. 분야명·장번호·정규식은 예전에 사용한 숫자(예: 제01~04장, 제14~15장)를 전범위의 영구 매핑으로 가정하지 않는다. 채권법·친족법·상속법 출제 시 원본 DB에 실제 등록된 장명과 안정키 분류를 필요한 범위에서 확인한 후 B8을 구성한다.
3. 범위별 가중 출제가 한 브리지에서 직접 보장되지 않는 경우, 각 분야별로 브리지를 순차 설정하여 해당 분야 후보의 표시 순서 상위 N개를 그대로 고른다. 각 묶음은 별도 정식 세트ID로 세트관리에 먼저 등록하고, 사용자에게는 연속된 OX 10문제로 제시한다. 답안 제출 시 사용자에게 제시한 전체 번호와 세트별 번호·안정키를 정확히 대응시킨다.
4. 미래에 통합 혼합 브리지가 실제 구축·검증되면 한 세트로 처리할 수 있다. 구축 전에는 그러한 자동 기능이나 통합 기록이 있다고 주장하지 않는다.

## 4. 고속 출제 실행 절차
1. 신규 출제 전 GPT브리지_1차의 전체 상태를 반드시 확인한다. '정상'이 아니면 새 출제를 중단하고 상태를 보고한다.
2. 범위별: B7:B10 설정 및 이전 선택키의 안전한 정리 → A17:H136 후보 상위 N개 확인 → 해당 안정키만 K17:K56에 묶음 기록 → L:S 선택 문제·S 기준시각 읽기 → B11 기준 세트관리 A:G 다음 빈 행에 추가한다.
3. 고정된 시트 ID와 구조는 같은 작업에서 반복 조회하지 않는다. 가능한 읽기·쓰기는 묶음으로 처리하고, 진행 안내나 중복 재조회는 줄인다. 그러나 후보 순서·상태확인·기록 검증을 속도 때문에 생략하지 않는다.
4. 문제 출제 시 사용자에게 문제본문만 제시한다. 답안 제출 전에 GPT채점키_1차·비공개 정답·해설을 읽거나 공개하지 않는다.

## 5. 답안 제출 후 공식 채점·기록
1. 제출 답안수 및 세트별 문항번호·안정키 대응을 먼저 검증한다. 답안 제출 후에만 해당 정식 세트의 GPT채점키_1차를 읽는다. 마지막 브리지 선택에서 밀려난 앞 묶음은 해당 안정키의 비공개 채점키 행만 좁게 조회한다. 정답키 전체를 읽지 않는다.
2. 1차 OX는 문항별 정답 1점, 오답 0점. 전체를 일괄 채점한다.
3. B12 기준 OX정답키 A:G, B13 기준 풀이이력 A:L의 다음 빈 행에 기존 기록을 보존하면서 묶음 추가한다. OX정답키 H열과 풀이이력 M:Q의 자동수식은 건드리지 않는다.
4. 세트관리 F열은 해당 세트가 실제 기록되었을 때만 '예'로 바꾼다. 가능하면 한 묶음 쓰기로 처리하고, 기록 후 10건 수·원답·점수·안정키·제출 상태·자동검증을 필요한 범위만 재조회한다.
5. 기록 실패·권한 오류·안전 검사 차단 시 성공으로 보고하지 않는다. 기존 행을 삭제·덮어쓰거나 우회해서 수정하지 않는다.

## 6. 기본서·오답 이해·백지복습
1. 오답에 한하여 기본서_색인.csv로 관련 분할 Markdown 범위를 찾고 필요한 법리·판례를 확인한다. 필요할 때만 같은 PDF의 실제 쪽을 대조한다. 확인한 파일명 및 PDF 페이지를 표시하고, 확인하지 못한 내용은 추측하지 않는다.
2. 설명은 최산·송민기·정우영 사례로 '당사자 관계 → 문제되는 권리 → 조문상 원칙 → 판례의 구체적 판단 → 결론' 순서를 따른다. 정답 문항의 긴 해설은 생략한다.
3. 필요하면 짧은 회상 질문 1~2개를 제시하고 답변 전 정답을 공개하지 않는다. 공식 OX 점수·풀이이력에 회상 평가를 혼입하지 않는다. 사용자가 다음 정식 세트를 요청하면 복습을 강제하지 않는다.
4. 새로운 채권법·친족법·상속법을 읽어도 위 해설 절차는 동일하다. 새 과목마다 새 해설 규칙을 작성하지 않는다.

## 7. 적용 경계
- 이 문서는 '출제 범위·비중·작업 속도'를 동적으로 조정하는 추가 규칙이다. 원본 시트, 수식, 채점키, 출제 순서, 과거 학습이력, 기본서 단원ID를 변경하는 승인이 아니다.
- 공식 2차 사례 출제·채점은 기존 GPT브리지_2차 및 상세 지침 v3를 따른다. 1차의 3:7·신규 영역 6~7 규칙을 2차에 기계적으로 적용하지 않는다.
- 분야 확대는 사용자의 누적 학습범위 값 변경으로 처리한다. 학습범위·출제비중의 변경만을 이유로 추가 운영 지침을 계속 만들지 않는다. 별도 지침 개정이 필요한 경우는 DB 스키마나 실제 출제 기능이 바뀌는 때뿐이다.
- 이 파일을 사용자에게 전달하는 행위는 ChatGPT 프로젝트 설정을 자동으로 변경하는 행위가 아니다. 기존 고속 운영 v1 문구는 프로젝트 설정에서 이 v2로 한 번 교체하고, 이후 진도 확대 때는 진도만 전달하면 된다.
