# Exam progress read service

`getExamProgress(pool, { ownerId, subjectId, stage, cursor, limit })` reads published exam problems, owner-scoped committed native grades, and imported Sheet history. It does not read answers or private grading keys and does not write to the database. The public `getCivilExamProgress` MCP tool obtains `ownerId` from the verified WorkOS context, never from tool input. `limit` is 1–100; `nextCursor` is a stable key for the next page. Pagination does not claim a transactionally frozen snapshot across calls.

For native P2 history, a grade row counts as an attempt only when the same submission and problem has a nonblank `original_answers` row. The SQL checks existence and does not return answer text. A zero-point placeholder for an unsubmitted subquestion therefore cannot increase attempts or drive review/mastery.

The independent test Sheet's effective rule is: valid attempts require an existing problem key, nonempty original answer, completed grade, attempt date, score, positive maximum points and a grading key. The latest score is the average score rate among valid attempts on the latest attempt **date**. The current native ledger has one committed grade per submission and the service instead orders attempts by exact commit timestamp. This difference needs parity testing for multiple grades on one day.

Review due: latest valid attempt date + 7 days after one attempt, + 21 after two, + 60 after three or more. Sheet timezone is Asia/Seoul. Current service uses UTC instants for native timestamps; date-boundary parity is not yet confirmed. Selection priority is missed/low score below 66.7%, then review due, then source change. The exact selection service owns this rule.

For P2, the seven independent 0–2 diagnostics yield a structural rate out of 14. A requires structural rate at least 85%, actual point rate at least 66.7%, and every diagnostic above zero. B requires structural rate at least 70% and actual point rate at least 66.7%; C requires at least 50%; otherwise D. An A is recognized only when more than three days after the preceding A on that problem. Two recognized A results mean pass; three mean graduation. The official awarded/max point rate is separate from these diagnostics. For P1, the latest grade's 66.7% threshold is a provisional pass signal; the Sheet has no P1 A/graduation rule.

Imported `SHEET_HISTORY_IMPORTED` payloads have score, maximum points, validity and set ID, but not the original attempt date or P2 seven diagnostics. The import event timestamp is not an attempt timestamp. A row with matching native set ID is deduplicated; any remaining imported row makes mastery/pass/graduation **ambiguous** and returns null, never a guessed status. An import without set ID may also duplicate a native attempt, so its count needs reconciliation before production use. A `PREPARED` submission with a nonblank original and no committed grade is **pending_grade**: it is never counted as unattempted or completed, and the user sees `확인 필요`. The service reports owner-scoped totals by stage: published, completed with verified native answer/grade, unattempted, and unknown for unresolved imports or pending originals. `overallStatus: "partial"` means at least one unknown item. Aggregate pass/graduation counts remain unreported until imported P2 seven-element history is reconciled. The concept `learner_progress` table is intentionally unused.
