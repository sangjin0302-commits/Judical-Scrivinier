문서 ID는 사용자 제공 원본이다. 이번 작업은 이 문서의 전체 내용을 가져오거나 공식 원장을 재구축하지 않았다.

## 감지와 비교

1. 마지막 승인된 문서 버전·수정시각·문항 구간 해시를 비공개 유지보수 저장영역에 기록한다. GitHub에는 원문·정답 해시 목록·개인 기록을 올리지 않는다.
2. 제공되는 revision ID 또는 수정시각을 비교한다. 수정시각은 변경 신호일 뿐 변경 내용의 증거가 아니다.
3. revision 차이를 가져올 수 있으면 변경 구간만 읽는다. 제공되지 않으면 승인된 유지보수에서 문서 스냅샷을 한 번 읽고 비교한다. 일상 학습마다 전체 문서를 읽지 않는다.
4. 문항 원본 ID로 경계를 나눈다. 공백·줄바꿈만 정규화한 비교와 원문 비교를 구분한다. 숫자·부정어·조건·조문·판례번호는 제거하지 않는다.
5. 기존 원본 ID↔안정키 대응을 조회한다. ID 없음·중복·경계 모호함은 자동 신규 등록하지 않고 격리한다.

## 분류와 처리

| 변화 | 처리 제안 | 자동 수행 금지 사항 |
|---|---|---|
| 신규 ID | 출처·중복·필수 필드 확인 후 새 안정키 부여 제안 | 제목 유사도만으로 안정키 확정 |
| 기존 본문 수정 | 기존 안정키 유지, 새 문항 버전 제안 | 과거 문제 버전 삭제 |
| 중복 후보 | 원본 ID·본문·출처를 함께 비교해 검토 | 기존 키 합치기·이력 이전 |
| 삭제 후보 | 원문에서 사라진 사실과 원인을 검토, 비활성 제안 | 원장 행·과거 세트 삭제 |
| 정답·해설 변경 | 명시적인 유지보수 승인 후 제한된 키 대조와 근거 검토 | 학습 전 키 열람, 과거 자동 재채점 |
| 연계 보강 | 기존 단원ID·안정키·근거 확인 후 연결 제안 | 근거 없는 단원 자동 연결 |

## 버전 보존

안정키는 같은 문항의 정체성, 문항 버전은 그 시점의 본문·기준, 세트ID는 실제 출제 사건이다. 기존 자료 기준시각을 보존하고 향후 버전 저장영역에 `안정키, 문항버전, 원문버전, 적용시각, 검토상태`를 연결하는 방안을 제안한다. 현재 세트관리 G열만으로 정확한 과거 본문 복원이 가능한지는 미검증이다.

버전 저장영역·새 열·새 탭은 이번에 만들지 않는다. 승인 후 보호된 별도 구조에 필요한 과거 버전을 보관하고 기존 공식 이력은 변경하지 않는다. 기존 키로 최신 본문을 조회했다고 과거에 풀었던 본문이라고 단정하지 않는다.

## 승인 후 적용 절차

변경안 작성 → 대상 키·필드별 검토 → 원본 백업 및 복원 가능성 확인 → 분리된 검증환경에서 비교 → 사용자 승인 → 좁은 범위 적용 → 키 무결성·후보 순서·채점 연결·기존 이력·수식 확인.

적용 묶음마다 식별자와 변경 전후 해시를 남긴다. 재시도는 같은 묶음의 미반영 항목만 처리한다. 실패 시 새 출제를 멈추고 변경된 범위만 복구한다. 그사이 생긴 정상 학습이력을 옛 백업으로 덮어쓰지 않는다.

기존 문항 전체의 법리를 매번 재검증하지 않는다. 구체적인 오류·법령 개정·판례 변경 신호만 별도 검토하며 법령, 판결, 해석자료를 구별한다.
