# 문제 전용 통합 현황

기준: `origin/main`에서 새 `integration/civil-exam-only` 브랜치. 기존 PR #1(개념 교수법)·#2(고속 출제)·#4(PostgreSQL 통합)을 통째로 병합하지 않는다. PR #3 book-to-skill은 별도 유지한다. 검증된 공식 문제·인증·DB·Docs 코드만 선택적으로 가져왔다.

## 운영 경계

- WorkOS 인증 MCP 사용자 도구는 P1 출제·채점, P2 출제·원답 확정·채점기록 **5개**.
- Docs 대조·증분 미리보기는 기존 유지보수 토큰으로 보호한 POST 경로. 승인 없는 11건 내용 차이는 적용하지 않는다.
- 런타임은 `MCP_DATA_BACKEND=postgres`만 허용한다. 설정 누락 시 실패하며 Apps Script·Sheets 경로로 되돌아가지 않는다.
- 기존 Railway DB의 개념 테이블·학습기록, 공통 문제·세트·원답·성적 테이블은 삭제하지 않는다. 새 브랜치에서 개념 사용자 기능 코드만 제외한다.

## main 병합과 운영 전환의 차이

코드 PR 검사는 자동시험·빌드·비밀정보·기존 기능 회귀를 확인한다. 실제 운영 전환은 별도로 P1/P2 후보 선택 규칙의 Sheets 동등성, 실제 원답의 공식 기준 기반 채점 정확성, Docs 승인 변경 적용·롤백, 데이터/백업 대조, WorkOS·ChatGPT 종단 호출을 통과해야 한다. main 병합과 운영 DB 전환은 각각 사용자 최종 승인이 필요하다.

## 현재 확인된 차단조건

- PostgreSQL 후보 선정은 현재 요청 ID 기반 해시 정렬이다. 기존 Sheets의 범위별 할당량, 취약 모드, P2 사례 그룹 선택·소문항 확장과 동등하지 않다. 실제 시트 수식과 고정 후보 표본을 읽기 전용으로 대조해야 한다.
- P2 의미 평가의 근거 앵커·형식 검사는 AI 판정의 실질적 정확성을 보장하지 않는다. 실제 PREPARED 원답은 보존하며, 공식 배점 근거 확인 전 채점 완료로 바꾸지 않는다.
- Docs 본문 차이 11건은 사용자 승인 없이 적용하지 않는다. 새 문제·승인된 수정의 증분 적용은 격리 DB에서 검증하고 실제 입력원 기준 분류를 추가 확인한다.

운영 전환 후 계획: 기존 문제 Sheets는 데이터·수식·탭을 유지한 **읽기 전용 보존본**으로, 개념 Sheets는 **비활성 보존본**으로 관리한다. 이 계획은 전환 승인 전 기존 파일 권한·내용을 변경하지 않는다.
