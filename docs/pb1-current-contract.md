# PB1 현행 실행 계약 확인

확인일: 2026-10-27 KST. 결론: 저장된 PB1 코드가 운영 원본을 가리키는 것은 확인했다. 그러나 기존 브리지와의 동등성 및 기록 안전 조건을 충족하지 않는 부분이 있어 현재 통합 경로의 실행은 보류한다. 코드 수정·저장·함수 실행·정답키 값 조회는 하지 않았다.

## 확인 경로와 증거 수준

- Chrome에서 기존 Apps Script 프로젝트 편집기를 읽었다: https://script.google.com/u/0/home/projects/1hK5qX4L1_rl0riOMJFTR15sMV9YeIzzgmUCRIoRPw95ZsHCwpFsAmgkD/edit
- 프로젝트 표시명: 2027 법무사 동차_민법. 파일: Code.gs, Project Bridge.gs.
- 편집기 콘텐츠를 선택·복사하여 읽었다. 저장 버튼은 비활성 상태였고 입력·붙여넣기·실행·배포를 하지 않았다. 소스 전체를 저장소에 복제하지 않았다.
- 아래 줄 번호는 이번 읽기 시점 Project Bridge.gs의 줄 번호다. 이후 코드 변경 시 달라질 수 있다.
- 이전 채팅의 배포/시험 보고보다 이번 현행 코드 직접 확인을 우선한다. 과거 보고가 현재 코드의 안전성을 보장하지 않는다.

## 직접 발견한 불일치

1. **후보 필터가 다르다.** 기존 1차 A17은 활성·1차 OX 외에 Z=아니오, X=있음 조건을 적용한다. PB1은 N=변경없음을 대신 검사하며 Z/X 조건이 없다. 범위 정규식도 기존은 Q와 F를 합쳐 검사하지만 PB1은 Q만 검사한다. 현재 데이터에서 실제 후보가 달라지는지는 실행하지 않아 미확인이다. 동등성은 주장할 수 없다.
2. **세트ID가 TEST-P1-로 고정되어 있다.** prepare가 운영 원본에도 시험 접두어를 쓴다. v3의 P1-YYYYMMDD-HHMMSS 운영 계약과 다르다. 같은 초의 중복 ID 검사도 보이지 않는다.
3. **셔플 시드가 자동 갱신되지 않는다.** 통합 B3에 숫자가 있으면 매번 그 값을 재사용한다. 새로운 시드를 설정한다는 별도 계약이 필요하다.
4. **선택 용량·영역 중복을 막지 않는다.** K17:K56을 비운 뒤 n행을 쓴다. n≤40 검증, 정수 문항수 검증, 영역 간 안정키 중복 제거/차단은 해당 PB1 본문에 없다.
5. **제출 표시가 너무 이르다.** grade는 채점키 확인과 기록 전에 모든 세트관리 F를 예로 바꾼다. 이후 키 누락·쓰기 실패 시 실제 기록이 완료되지 않아도 제출 표시가 남을 수 있다.
6. **키 조회 범위가 넓다.** 실제 코드가 GPT채점키_1차.getDataRange().getValues()를 호출한다. 비공개 원본 키 탭 전체와는 다르지만, 해당 선택 행만 좁게 읽는 지침과 일치하지 않는다. 이번에는 이 코드를 읽었을 뿐 키 값을 읽지 않았다.
7. **재제출·동시 실행 방어가 없다.** PB1 본문에는 LockService, 이미 채점된 세트 거부, 동일 세트·안정키의 기존 기록 대조가 없다. 포인터 B12/B13 사용만으로 중복이나 동시 충돌을 막지 못한다.
8. **앞 묶음·선택 변경을 처리하지 않는다.** grade는 현재 GPT채점키_1차의 키 집합에 의존한다. 다른 세트로 선택이 바뀌면 과거 묶음의 좁은 안정키 fallback이 없다.
9. **키 값·점수 검증이 부족하다.** 사용자 답안은 O/X 검사하지만 채점키 정답 자체가 O/X인지 확인하지 않는다. 쓰기 뒤 H/M의 비어 있음만 확인하며, 원답·점수·안정키·총 기록 수의 재조회 대조가 없다.
10. **부분 쓰기 복구가 없다.** OX 기록 뒤 풀이 쓰기가 실패해도 중복 없이 이어가는 절차가 PB1 본문에 없다. 기존 기록 삭제로 해결해서는 안 된다.
11. **공개 표시와 외부 호출 경로가 불명확하다.** prepare는 세트관리 E에 아니오를 기록한다. 사용자에게 실제 공개할 때 이를 어떻게 바꾸는지 호출 계약이 없다. Code.gs의 onOpen 메뉴는 makeSet/openOxDialog 등 기존 함수를 연결하고 PB1 참조는 없다. 두 코드 파일에서 doGet/doPost 정의도 찾지 못했다. Apps Script Execution API 배포·권한은 확인하지 않았다.

## 확인된 것과 아직 모르는 것

현재 편집기에는 PB1 prepare/grade 정의가 각각 하나다. Code.gs에 PB1 참조가 없고, Project Bridge.gs의 PB1 블록 안에는 잠금 호출이 없다. 다만 운영자가 별도 외부 실행 경로로 잠금을 걸 가능성까지 부정하지는 않는다. 그런 경로는 이번에 확인하지 못했다.

트리거 화면에는 필터 없는 상태에서 0개가 표시됐다. 이는 현재 계정에서 보이는 설치형 트리거 목록이며 다른 계정 소유 트리거 또는 외부 스케줄러의 부재를 증명하지 않는다. 실행 권한 유효성, 배포 버전, 실제 최근 실행 결과, Sheets 계산 성능은 실행하지 않아 미확인이다.

## 다음 조치

현재는 검증된 기존 범위별 브리지 절차를 유지한다. PB1 수정은 별도 원본 변경 승인 후 사본에서 진행한다. 후보 동등성·운영 ID·새 시드·용량/중복·제출 후 키·키 범위 제한·잠금·재시도·최종 기록 검증을 함께 시험해야 한다. 특히 PB1_testEndToEnd를 운영 원본에 실행하지 않는다. 이 문서는 실행 지시나 배포 승인 문서가 아니다.
