# Fixed P2 criteria experiment boundary

The current semantic audit accepts a caller-supplied decomposition. The same official source and answer can receive different scores if the caller omits or adds required elements. Source snapshots and post-commit idempotency do not fix this first-evaluation denominator.

`db/p2-fixed-criteria.mjs` supplies a private experiment helper. Create one manifest from the official model/rubric before evaluating candidate answers; retain it for every repeated evaluation. Validate each evaluation against that same manifest, then run the existing semantic audit. The manifest binds the complete criterion/category/evidence set and count to the normalized official source digest. Reordering is accepted; omissions, additions, duplicates, changed categories/evidence, or changed sources are rejected. Status judgments may vary and must be measured separately.

This helper neither approves criteria nor proves semantic completeness or correctness. A manifest and its digest must be retained by the trusted experiment runner; accepting a fresh caller-supplied manifest on every attempt defeats the check. Source digests identify content, not an authenticated grading-key version. Private manifests contain excerpts and must not be committed or printed.

**Conditional runtime integration, not deployed.** If the exact encrypted grading-key snapshot contains `fixedCriteriaManifest`, prepare validates and returns it after original submission; commit validates against that server-held manifest and records its digest/count in the semantic audit. A client-supplied manifest cannot replace it. Existing keys without the field retain their previous behavior. No live key has been updated or published, so this does not claim live grading now universally enforces a fixed denominator. Keep `P2_GRADE_COMMIT_ENABLED=false` until semantic acceptance and the approved criterion supply path are complete.

Production adoption requires a reviewed decomposition and an approved new key-version publication procedure. Adding the manifest changes the encrypted payload and must create a new immutable key version. Existing sets continue referencing the previous key snapshot and do not acquire the new manifest. Existing keys, grades and original answers remain untouched. Missing approved criteria should fail closed only once the supply path and legacy compatibility handling are implemented. No migration, automatic criterion approval, key publication, or production change is performed here.

The guarded localhost `exam-flow.integration.mjs` fixture appends a synthetic v2 key, verifies an already-prepared v1 set remains pinned to v1, rejects a reduced denominator and a caller-supplied replacement manifest with transaction rollback, and checks valid fixed-criteria grading and replay. Run it only against a fresh disposable `exam_flow_*` database on localhost port 55432. Fixture code presence alone is not a passed integration test.
